    PRD 和需求来源

    本地文件和飞书链接可以同时提供；当前版本会导入文件并登记链接。

    本地文件 Word、Markdown、PDF、Excel、截图附件等。

    保存后复制到当前 workspace 的 `prd/` 目录。

    飞书 / 外部文档链接 每行一个链接，可与本地文件同时使用。

    填入链接后可先读取到本地，成功后生成 `prd/document.md`。

    功能点定位 先导入 PRD，再从白皮书功能索引确认本次功能点；系统会加载关联应用、风险和推荐能力。

    需求上下文

    只填本次需求特有的信息；通用工具、能力库和应用索引由全局配置维护。

    涉及应用 优先从应用索引选择，找不到时再手动选目录。
    高级覆盖 本次额外 skills / rules / 分支规则，新用户通常不用填。
    什么时候需要填？ 只有当这次需求临时需要一个不在团队能力库里的 Agent 技能或规则时才填写。可以选一个目录，也可以选一个 Markdown 文件；每行一个路径。

    默认建议关闭。只有 PRD 已经明确涉及具体应用，并且希望需求分析 Agent 提前读代码时再打开。

    技术线索（可选） 有线索就补几句话；没有可以直接交给 Agent。

    自然语言补充

    不用填技术表格。写入口类、接口名、表名、历史坑、不能改的范围即可，Agent 会整理成方案产物。
