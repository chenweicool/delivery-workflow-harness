# 00 加载上下文

## 目标

加载公共知识快照，汇总本次需求需要用到的背景信息。

## 输出要求

- 输出必须是中文。
- 内容保持简洁，只写和本次需求有关的上下文。
- 没有证据的内容不要扩写；缺失信息只列具体缺口。
- 不要写泛泛兜底、免责声明或与后续阶段无关的建议。

## 允许读取

- `AGENTS.md`
- `CLAUDE.md`
- `context/**`
- `prd/**`
- 交付配置里的本地应用目录，仅用于识别候选应用、代码入口、业务术语和已有接口/模块边界。
- 如果存在 `context/domain-summary.md`，必须先读取该摘要；再按其列出的最小路径读取领域白皮书、领域记忆和本地可读代码。

## 禁止事项

- 禁止修改代码。
- 禁止生成实施方案。
- 禁止决定最终应用范围。
- 禁止做大范围代码审计；只提取和 PRD 直接相关的上下文线索。
- 领域资料只能作为背景和风险依据；PRD / 人工确认与当前代码存在冲突时，必须记录冲突，不得自行裁决。

## 输出

写入 `design/process/context-summary.md`。

## 输出结构

```md
# 上下文摘要

## 1. 需求概览

## 2. 已加载规则与上下文来源

需要区分：PRD / 人工确认、当前代码、领域 Harness 白皮书或记忆；注明各自的作用和版本（如可得）。

## 3. 业务术语

## 4. 候选系统范围

## 5. 已知风险

包括产品口径与当前代码、领域资料之间的冲突或证据缺口。

## 6. 缺失背景与待补充信息
```
